# 4.15 Internacionalização (i18n) — OPCIONAL

**Este documento só se aplica se o usuário pediu explicitamente para habilitar i18n neste projeto** (ex.: "adicionar i18n pt/es", "traduzir esta tela"). Por padrão, o projeto não usa `vue-i18n` — a pasta `app/core/i18n/` existe pronta mas está inerte (sem a dependência instalada). Não crie `lang/`, não chame `useI18n()`/`t()` nem presuma textos traduzidos a menos que i18n já esteja habilitado ou o usuário tenha pedido agora.

## Ativação (primeira vez no projeto)

1. Instalar as dependências (peça confirmação ao usuário antes de rodar):
   ```bash
   pnpm add vue-i18n primelocale
   ```
2. Registrar o plugin em `app/plugins/i18n.ts` (Nuxt plugin — não existe `createApp.ts` neste projeto):
   ```ts
   // app/plugins/i18n.ts
   import { i18n } from '@/core/i18n/createI18n'

   export default defineNuxtPlugin((nuxtApp) => {
     nuxtApp.vueApp.use(i18n)
   })
   ```
   Se o PrimeVue também for registrado via plugin próprio (`app/plugins/primevue.ts`), passe o locale do PrimeVue a partir de `i18n.global`:
   ```ts
   locale: (i18n.global.messages.value as any)[i18n.global.locale.value]?.primevue
       ?? (i18n.global.messages.value as any)['pt-BR'].primevue,
   ```

Ver `app/core/i18n/_OPCIONAL.md` para o mesmo passo a passo direto no código.

## Estrutura

Este projeto não usa `modules/<modulo>/`. As traduções específicas de uma área de domínio ficam num `lang/` próximo ao código dessa área (ex.: `app/lang/atividades/pt-BR.ts`, ou `app/components/atividades/lang/pt-BR.ts` — o local exato depende de onde essa área já está organizada; não force uma convenção `modules/` que não existe mais no projeto):

```
<algum lugar sob app/, próximo ao código da área>/
  lang/
    pt-BR.ts    ← obrigatório (sempre) quando essa área usa i18n
    es.ts       ← obrigatório se es.ts existe em app/core/i18n/locales/
    en.ts       ← obrigatório se en.ts existe em app/core/i18n/locales/
    [...]       ← todo idioma em app/core/i18n/locales/ é obrigatório também aqui
```

**Regra**: **todo idioma presente em `app/core/i18n/locales/`** (a fonte da verdade de quais idiomas o projeto suporta) é obrigatório também no `lang/` de qualquer área que use i18n — não há "idiomas opcionais" dentro de uma área já habilitada.

**Dicionário PrimeVue**: ao criar um novo idioma (`lang/<locale>.ts`), o dicionário interno do PrimeVue (`primevue: ...`) DEVE vir do pacote oficial `primelocale` — **nunca escrito à mão**. Importar assim:

```ts
// app/core/i18n/locales/<locale>.ts
import { <locale> } from 'primelocale/js/<locale>.js'
export default {
    primevue: <locale>,
    common: { ... },
}
```

Referência: `app/core/i18n/locales/pt-BR.ts` e `es.ts` já seguem este padrão. Para novos idiomas, consulte `primelocale/js/` para achar o locale disponível (ex: `pt_BR.js`, `es.js`, etc.).

## Common vs Área de domínio — Checklist de decisão

**Onde colocar cada chave de tradução?**

✅ **`app/core/i18n/locales/<locale>.ts` (namespace `common.*`)**:

- Ações genéricas reutilizáveis: `salvar`, `cancelar`, `adicionar`, `excluir`, `editar`, `filtrar`, `limpar`, `limpar_todos`, `buscar`, `selecione`
- Rótulos universais de campo: `status`, `data_inicio`, `data_fim`, `nome`, `filtros`
- Mensagens de erro genéricas: `erro`, `erro_carregar_opcoes`, `recarregar_pagina`
- **Pergunta-teste**: "essa string faria sentido com o texto idêntico em qualquer outra tela?" Se **SIM** → `common.*`.

❌ **Não coloque em `common.*`**: `periodo_matutino`, `situacao_agendada`, `coluna_vagas`, `campo_gestor` — essas são específicas do domínio.

✅ **`lang/<locale>.ts` (namespace `<área>.*`)**:

- Nomes de entidades e campos de negócio: `coluna_vagas`, `campo_gestor`, `campo_educador`, `campo_situacao`
- Valores de enum específicos do domínio: `periodo_matutino`, `periodo_vespertino`, `status_em_execucao`, `situacao_agendada`, `situacao_ocorrida`, `controle_presenca_com`
- Títulos e textos específicos da tela: `titulo`, `quantidade_atividades`, `registros`
- Breadcrumbs/navegação específica da área
- **Pergunta-teste**: "essa string é específica do domínio/entidade desta área?" Se **SIM** → `<área>.*`.

## Registrar as traduções

**Obrigatório** (quando a área usa i18n): mesclar os arquivos `lang/*.ts` na instância global do `vue-i18n` antes de a área ser usada, via `registerModuleLang` (nome histórico — a função só mescla o que o chamador descobrir via glob, não assume `modules/<modulo>/`):

```ts
import { registerModuleLang } from '@/core/i18n/registerModuleLang'

const langFiles = import.meta.glob('./lang/*.ts', { eager: true })
registerModuleLang(langFiles as any)
```

Chame isso a partir de um ponto que já é carregado quando a área entra em uso — por exemplo o `<script setup>` de um componente/página raiz da área, ou um plugin Nuxt dedicado, dependendo de onde a área foi organizada. Não existe mais um `router/routes.ts` por módulo como ponto de registro fixo — esse era um artefato da arquitetura antiga de módulos independentes.

## Usar nos componentes — traduções de chaves

**Regra**: nunca escreva string visível ao usuário hardcoded no template. Use sempre `t('chave')`.

```vue
<script setup lang="ts">
import { useI18n } from 'vue-i18n'
const { t } = useI18n()
</script>

<template>
  <h1>{{ t('atividades.titulo') }}</h1>
  <Button :label="t('common.salvar')" />
</template>
```

## Enums/Resolvers com traduções (padrão puro)

Enums e resolvers retornam **chaves**, não textos finais. A tradução acontece via `computed` na `view`/`composable`:

```ts
// enums/AtividadeEnums.ts — labels como CHAVES
export const periodoOpcoes: SelectOption[] = [
    { label: 'atividades.periodo_matutino', value: 'M' },
    { label: 'atividades.periodo_vespertino', value: 'V' },
    { label: 'atividades.periodo_noturno', value: 'N' },
]

// view/AtividadesView.vue — traduz no computed
<script setup>
import { useI18n } from 'vue-i18n'
import { periodoOpcoes } from '../enums/AtividadeEnums'
const { t } = useI18n()

const periodoOpcoesTraduzidas = computed(() =>
    periodoOpcoes.map(o => ({ ...o, label: t(o.label) }))
)
</script>

<template>
  <MultiSelect :options="periodoOpcoesTraduzidas" option-label="label" option-value="value" />
</template>
```

## Namespaces disponíveis

| Namespace    | Origem                              | Exemplos de chaves                                                            |
| ------------ | ----------------------------------- | ----------------------------------------------------------------------------- |
| `common.*`   | `app/core/i18n/locales/<locale>.ts` | `salvar`, `cancelar`, `filtrar`, `data_inicio`, `status`, `erro`              |
| `primevue.*` | `app/core/i18n/locales/<locale>.ts` | gerenciado internamente — não use direto no template                          |
| `<área>.*`   | `lang/<locale>.ts` da área          | `atividades.titulo`, `atividades.coluna_vagas`, `atividades.periodo_matutino` |
